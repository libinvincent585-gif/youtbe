# Loop — short video studio

A responsive short-form video app prototype with a video feed, upload details screen, and a small Node.js API.

## Run locally

1. Install Node.js 18 or newer.
2. From this folder, run `npm install`.
3. Run `npm start`.
4. Open `http://localhost:3002`.

The app's frontend and API are served together by Express when you use this URL. If you open `public/index.html` through VS Code Live Preview on port 3000, the frontend sends API requests to the local Express server on port 3002; start the app with `npm start` first.

Choose the centered **+** button to select a video, preview and trim it to 2 minutes or less, optionally add a soundtrack, add a caption, choose Public or Private visibility, and upload without signing in. There are no bundled/default videos: the feed starts empty until public uploads exist. A newly uploaded public video is shown first in Home immediately, with Shorts using the same refreshed feed and vertical player; the new upload attempts muted inline playback, and player controls remain available if browser autoplay is blocked. Videos are limited to 1080p maximum (4K is rejected). Video and soundtrack files may each be up to 2 GiB by default; configure `MAX_UPLOAD_SIZE_BYTES` to change this per-file limit. Upload requests and server-side video processing have a 2-hour timeout by default; configure `UPLOAD_TIMEOUT_MS` to change it. Trimmed videos are processed on the server with FFmpeg; install dependencies with `npm install` before starting the app. Uploaded files and feed metadata are saved under `uploads/`. Private videos are omitted from the public feed; uploaded media URLs are not protected by account access controls in this prototype.

Feed videos use a vertical 9:16 player with a floating right-side Like, Comment, WhatsApp Share, and Save rail; creator avatar and Follow control overlay the video. Likes are stored locally in the current browser. Guests can browse the Home and Shorts feeds without signing in. The **Subscriptions** and **You** tabs require authentication and send Guests to login or sign-up; after success, the app opens the protected destination. Creator headers open creator profiles with their public video grids. The **Subscriptions** tab opens the current creator's profile, including their avatar, post/follower/following counts, profile details, and public uploaded-video grid. Videos uploaded while signed in are associated with that account and can be deleted by their owner from this grid; deleting a video also removes its comments, media, and optional soundtrack. Signed-in users can upload a JPEG, PNG, or WebP profile picture up to 5 MiB; avatars and profile details are saved server-side in `accounts.json`, and images are stored under `uploads/`. The profile settings dialog provides profile editing, private-account and notification preferences, post management, password changes, blocked-user controls, help/feedback, and logout. Private accounts hide profile details and videos from non-followers in application API responses; direct uploaded-media URLs are not access-controlled. Notification settings are saved, but push delivery is not configured in this prototype. Feedback is saved in `feedback.json`. If the followed-user service returns an unexpected response, the profile still loads and valid saved follows are used as a fallback. Profiles show post, follower, and following counts; follower and following counts open user lists with Follow, Following, and mutual Friends states. Sign-up collects a username, email, password, and confirmation; login collects only email and password. Google Sign-In is currently disabled; use the standard email/password forms. Accounts and scrypt password hashes are stored server-side in `accounts.json`, and sessions use an HttpOnly cookie. Successful sign-up outside a guarded navigation returns to Home; authentication started from Subscriptions or You opens that destination after success. Email ownership is not verified, and this is not production-ready authentication. Signed-in users can log out from the profile header or settings; logging out clears the current session and returns directly to Home as Guest. Creator profession/bio/interests are edited in a dedicated modal and are saved with the account. Posts count uploaded public videos because this prototype has no separate post-creation feature. Follow relationships are saved by the server in `relationships.json`; the client-supplied usernames are not authenticated, so these relationships are prototype-only and can be spoofed. Comments are stored with the video metadata. Downloads are delivered through the browser's normal download flow; a web page cannot force a file into a phone's photo gallery.

## Prototype limitations

Anonymous uploads and feed videos are public to anyone who can reach the server. This is for local demonstration only. A production deployment should add account authentication, upload authorization and rate limits, protected private media, and appropriate upload scanning and storage controls.
